# Agent Guidelines

## Getting started

- This repository uses **Vite+** over Yarn 4 in classic `node_modules` mode. Install dependencies with `vp install --frozen-lockfile`.
- Tool configuration is tracked directly in the repository; there is no generated scaffold step.
- The primary verification flow matches `.github/workflows/ci-cd.yml`: run `vp run build` followed by `vp run test`. Vite+ runs Oxfmt, Oxlint, TypeScript checks, Vitest, and tsdown/Rolldown packaging.
- Run `vp fmt` before committing changes. Tool configuration belongs in `vite.config.ts`.
- During performance experiments, serialize benchmark runs, builds, and test suites across worktrees with `python3 /absolute/path/to/benchmark/queue.py --label NAME -- COMMAND`. All worktrees use the same per-machine FIFO lease. Timing and memory runners reject commands without a lease. Lightweight edits and reads may run concurrently.

To run tests, or run any command that requires the internet, you must execute the task with `{with_escalated_permissions: true}`.

## Code generation boundaries

- Refresh `src/models.gen.ts` from OpenAI's live model catalog with `yarn scrape:models`, then run `yarn codegen` to update the derived model artifacts. See `src/scraper/README.md` for the automated discovery pipeline, manual fallback, and review workflow.
- The following outputs are generated by scripts and must not be edited manually:
  - `src/bpeRanks/**/*.js` — generated from the `.tiktoken` files in `data/` via `yarn codegen:bpe` (`src/codegen/generateJsBpe.ts`).
  - `src/model/**/*.ts` — generated from the encodings in `src/encoding/` via `yarn codegen:models` (`src/codegen/generateByModel.ts`).
  - `src/modelsChatEnabled.gen.ts` — generated from `src/models.ts` via `yarn codegen:chat-enabled` (`src/codegen/generateChatEnabled.ts`).
- Raw benchmark timing JSON is produced by `benchmark/src/benchmarkRunner.ts`; separate settled one-pass memory JSON is produced by `benchmark/src/memoryRunner.ts` (five fresh processes per case/engine). Run both timing engines first, then both memory engines, as documented in `benchmark/README.md`.
- Benchmark publication: `benchmark/RESULTS.md` and `docs/{fastest,lowest-footprint,initialization}.png` are generated by `benchmark/report.py` from the committed raw JSON in `benchmark/results/`. Install `benchmark/requirements-report.txt` and run `python3 benchmark/report.py`; change the report script or measurement inputs rather than editing generated results.
- `src/encodingParams/unicode16Data.ts` is generated by `python3 src/codegen/generateUnicodeProperties.py --unicode-data /path/UnicodeData-16.txt --unicode17-data /path/UnicodeData-17.txt` from hash-pinned official Unicode data. See `src/codegen/UNICODE.md`; do not edit the generated ranges directly.
- `src/__fixtures__/unicode16Tokens.json` is generated by `src/codegen/generateUnicodeTokenFixtures.py` using official Python `tiktoken==0.14.0` and the same Unicode data; regenerate with the documented script rather than changing expected token IDs manually.
- `benchmark/experiments/snapshots/*` are generated by `python3 benchmark/experiments/snapshot.py` from self-contained sanitized extracts in `benchmark/experiments/snapshot-sources/`. Historical corpus-v2 input hashes remain unchanged; future runs use corpus v3. Change source extracts or the generator and regenerate; do not edit or format generated workloads manually.
- Optimization publication: `benchmark/experiments/overview.py` generates `benchmark/experiments/OVERVIEW.md` from complete publication-budget realistic raw runs; `benchmark/experiments/legacy-report.py` generates scoped legacy result tables. Change the generators or raw inputs rather than editing their output tables.
- `benchmark/experiments/charts.py` generates `docs/optimized-{latency,footprint,realistic}.png` from the matching validated Node/o200k timing, settled memory, and realistic raw JSON. Keep historical baseline charts unchanged.
- `benchmark/experiments/summary-chart.py` generates `docs/benchmark-summary.svg` from validated scoped Node/o200k raw timing JSON; `publish.py --charts` regenerates it too.
- `benchmark/experiments/diagnostics/regex/oracle.json` is a frozen official-Python correctness oracle owned by the archived `oracle.py` beside it. Preserve the recorded hashes and source version; do not format or manually rewrite historical diagnostics/rejected experiment artifacts.
- `benchmark/experiments/publish.py` validates and regenerates `benchmark/OPTIMIZED-RESULTS.md`, scoped legacy/realistic result tables, `benchmark/experiments/OVERVIEW.md`, and the separate consumed-output/longer-confirmation `*-RESULTS.md` reports from a complete frozen raw prefix. Use its `--charts` option to regenerate the optimized PNGs too.
- `benchmark/experiments/profile-count.mjs` generates the separate unranked long-README count CPU diagnostic JSON. It records sampling proportions, not publication throughput ranks.
- Generated files now contain a header comment describing the owning script and the command to regenerate them. Always modify the source templates or data (e.g. files under `src/codegen/`, `src/encoding/`, or `data/`) and rerun the corresponding script instead of editing generated outputs directly.

## Project structure notes

- TypeScript source lives under `src/`. Common entry points are `src/main.ts` and the modules in `src/encoding/`.
- Tests are written with Vitest (`vp test`). Snapshot files reside next to their test files inside `src/__snapshots__`.
- Keep the repository compatible with both ESM and CommonJS builds; avoid introducing Node-specific globals without appropriate guards.

## Pull request expectations

- Include clear descriptions of functional changes and reference any relevant commands run locally.
- When adding new scripts or codegen steps, update this file if they produce additional generated artifacts.
